WHY THIS FILE EXISTS
--------------------------------------------------------------------------------
A program in a package is anonymous. This file is how anyone later can tell
which executable came from which source, which toolchain and which build
machine. Every time a program is adopted into ../../native_libraries/<rid>/,
its section here is updated from that build's output/<rid>/BUILD-INFO.txt and
the <program>.provenance.txt beside it is written from the same values.

ADOPTED 2026-11-23 - the main module of a split build keeps its data: linux-x64
and linux-arm64 (win-x64, osx-arm64 and osx-x64 NOT YET REBUILT)
================================================================================
(The times below are UTC, which was already 2026-11-24; the builds ran on the
afternoon of 2026-11-23, Pacific time.)
Why: in a split build (`dx build --wasm-split`), text formatting in the MAIN
module could give an empty text: `format!("{}{}", a, b)` gave "". The
platform's REST client builds every address with that expression, so an
application's calls failed before a request left the browser. Cause: the
linker stores a constant that is the tail of a longer one inside the longer
one (two overlapping data symbols), and the splitter (wasm-split-cli 0.7.10)
zeroed, in the main module, the whole range of every data symbol only split
modules reach - and with it a main-module constant stored in that range.
Upstream: issue DioxusLabs/dioxus#5769 and pull request #5772 (the same
change), both open. Made under the repository owner's GO of 2026-11-23.

    (vendoring/wasm-split-cli/PATCH-NOTES.txt): prune_main_symbols leaves
    alone the bytes a data symbol the main module keeps covers. FOUR splitter

  * dioxus-cli unchanged: still SEVEN patches; its Cargo.lock unchanged;
  * wasm-bindgen, both licence files and both notices files that travel with
